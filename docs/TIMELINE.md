# LeadSphere Timeline

## Architecture

The Ticket tab and global navigation page render the same `TimelineWorkspace`. The browser sends filters to Supabase RPCs; PostgreSQL performs Ticket authorization, timezone grouping, aggregation, filtering, and detail pagination before returning chart-ready JSON.

Authoritative sources:

- Activity: immutable `crm_ticket_activity` rows already written by Ticket, request, assignment, note, transfer, deletion, and Follow Up workflows.
- Email and Call: `crm_ticket_communications`. The current application records a genuine `INITIATED` communication when an authorized user launches the existing Email or Call action. It does not claim the message was delivered or the call was completed.

No event is written when a user views the Timeline.

## Scope and privacy

- Every query enforces `crm_can_access_ticket(ticket_id, 'tickets.read')` inside PostgreSQL.
- Global filters are applied before aggregation and pagination.
- Communication table access is revoked from browser roles. Clients must use the redacting RPCs.
- Communication-sensitive fields are returned only to users with `activities.read` or to the user who initiated the communication.
- Recording columns are reserved for a future integration. No URL or playback control is exposed by the current UI.

## Time handling

Timestamps remain UTC (`timestamptz`). Range boundaries and day/week/month buckets are calculated in `Asia/Colombo`. The end date is converted to an exclusive boundary at the start of the following local day.

Grouping is selected automatically:

- Up to 31 days: daily
- 32–180 days: weekly
- More than 180 days: monthly

Chart buckets are displayed newest-first so the current day or current grouping period is visible immediately without horizontal scrolling.

Custom ranges are limited to 730 days.

## Database functions

- `get_crm_timeline`: authorized server-side aggregation.
- `list_crm_timeline_details`: authorized, redacted, paginated bar details.
- `get_crm_timeline_filter_options`: authorized global filter choices.
- `search_crm_timeline_tickets`: debounced authorized Ticket search.
- `record_crm_communication_launch`: idempotent Email/Call launch recording.

## Current integration boundary

LeadSphere does not yet integrate with an email provider, telephony provider, or recording service. Consequently, only real launch events can be generated by the current UI. Delivery, inbound communication, duration, attachments, previews, and recordings remain empty until a trusted provider integration writes authoritative values to the normalized communication model.
